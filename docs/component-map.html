Shreyas Kulkarni, Portfolio Site: Components Map (plan)

A portfolio site for the six projects in GitHub account kulkarnishreyas87-boop. Neon (Postgres) is the system of record for every project, its stack, highlights, media and repo facts. A daily sync reads GitHub and keeps the facts fresh. Gemini only drafts write-ups from READMEs, and nothing is published until I approve it in the admin page. The public site reads only from Neon. This is a map only: nothing on it is built yet.

One sync, step by step

  1. Cron (or Sync now) calls /api/sync with the cron secret. A sync_runs row is opened.
  2. The GitHub API lists public repos. A new repo becomes a hidden project row, so nothing appears without my say.
  3. For each repo: stars, languages, last commit and homepage go into repo_snapshots. Dependencies become stack tags.
  4. If the README hash changed, Gemini writes a draft into drafts. Otherwise no AI call is made.
  5. I open /admin, review or edit the draft and publish. Neon is updated and the pages are refreshed.

Why this shape

  • Neon as the single source. The site never calls GitHub or Gemini while a visitor waits, so pages load fast and keep working if either is down.
  • Gemini drafts, I publish. The write-ups speak for me to recruiters, so nothing AI-written goes live unread. Same rule as Skinstinct Draft Lab.
  • Hand edits win. edited_fields records what I changed, and the sync never overwrites those fields.
  • Facts stay fresh by themselves. Stars, last commit and stack update daily with no work from me.
  • Same stack as my recent work: Next.js, Neon, Gemini, Resend and Vercel Cron, as in Pulse-AI.
